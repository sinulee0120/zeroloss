> 조사 방법: 웹 검색(Exa)으로 제품 공식 페이지·특허 공보 요약을 확인. **법률 판단이 아니다.** 공개·상용화 전에는 변리사·변호사 검토가 필요하다.

**ZeroLoss가 다른 점(실제로 남는 차이)**
- 개발 중인 **공유기 펌웨어**를 대상으로, 일반 PC·태블릿만으로 **100시간 무손실** 스트리밍을 검증.
- **도구·수신 장비 원인을 공유기 탓에서 분리**(보라 판정, 송신 원인 판별 05 3.4-1)하는 판정 규칙.
- 모든 기능을 CLI로 열어 **AI(Claude)가 빌드→배포→시험→분석을 반복하는 폐쇄 루프**(13장), 표준 추적표(17장).
- 이 차이들은 "설계의 장점"이지 **진입 장벽(해자)은 아니다.** 상용 제품들도 API·자동화를 이미 갖췄다.

### 1-1. 장단점 (기존 제품 대비, 2026-09-26 정리)
> 위 표의 제품과 견준 것. **아직 실제 공유기로 재 본 적이 없으므로 장점은 설계상의 장점이다.**

| 장점 | 근거(어디에 있나) |
|------|-------------------|
| 개발 중 공유기 펌웨어의 **100시간 무손실 스트리밍 검증**에 맞춤(기능 적합성·양산 검사 중심인 제품들과 목적이 다름) | 01 통과 기준, 05 5.3~5.4 |
| **원인 분리:** 손실을 공유기 / 수신 장비·도구(보라) / 송신 원인으로 나눠 판정 | 05 5.3, 05 3.4-1 |
| **초기 펌웨어도 시험:** IGMP·M2U가 없는 개발용·SDK 공유기는 프라임 방식으로 자동 전환 | iptv 4.5, S-18 |
| **사람 손 최소:** 공유기는 공장 설정 그대로(송신 PC가 통신사처럼 WAN 주소를 줌), Wi-Fi 연결·사전 점검·장애 뒤 Reset 자동 | 07 3.2, 03 F17·F11 |
| **값싼 장비:** 일반 PC·태블릿, 전용 계측 장비 불필요 | 01 |
| **AI 폐쇄 루프:** 모든 기능이 CLI로 열려 있어 빌드→배포→시험→분석을 되풀이 | 13 |
| 무료·공개 가능 | 3장 |

| 단점 | 메우는 방법 |
|------|-------------|
| **실측 검증 0회** — 자동 시험은 모두 루프백·가짜 장비 | 04 P1·P2 실기 항목(장비가 오면) |
| **정밀도 한계:** 하드웨어가 아닌 커널 수신 시각(ms 단위 지터·150 ms 기준에는 충분, µs 비교는 못 함) | 10 1.5 서로 다른 방법끼리 대조 |
| **규모·범위가 작음:** 태블릿 3대·PC 수신만(수천 가입자 흉내·표준 시험 수백 개 없음) | 필요하면 2차 모듈 |
| **무선 환경 통제 없음:** 차폐 상자가 없어 주변 Wi-Fi 간섭이 섞일 수 있음 | Wi-Fi 채널·AP 변경 기록(05 1.9), 장기 희망(01) |
| **미완성:** 태블릿 앱·Windows 설치 아직 없음(설정 화면 F14·Agent Desktop F20은 2026-09-26 됨) | 04 P3·P4 |
| **해자 없음:** 차이는 목적과 편의뿐 | 판매하지 않으므로 문제 아님(3장) |

- **"정말 더 좋은가"를 증명하는 법(장비가 오면, 제안):** ① 정확도 — 알고 있는 손실·지터를 넣고(10 1.3 netem) ZeroLoss 결과를 독립 측정(패킷 캡처·tsp 분석, 10 1.5)과 비교 ② 편의 — 지금 손으로 하는 시험 한 번(연결·설정·재생·기록·정리)의 시간·사람 손을 같은 시험의 ZeroLoss와 비교.
