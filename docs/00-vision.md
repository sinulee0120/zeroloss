# 00. 큰 목표 (Vision)

> **사람이 들어가지 않는 검증 시험실.** 큰 건물 안의 검증 조직·장비를 **모두 외부에서 조정**한다.
> 권한 있는 사람이 어디서든(외부 PC, 휴대폰) 지시하면, 인터넷에 연결된 Controller(와 Claude AI)가 시험실 안의 장비를 지휘해 시험하고, 결과를 보고한다.

**최종 목표: 디지털 노마드.** 해외 어디서든 시험을 지시하고, 결과물(보고서)을 받아볼 수 있다.

## 의도와 범위 (오해 없도록)
> 이 도구가 무엇을 위한 것이고 무엇이 **아닌지** 분명히 한다. 공개하거나 남이 코드를 볼 때 오해가 없어야 한다.

- **누가·왜:** 공유기·태블릿·전자장비를 좋아하는 **개인**이, **자기가 검증하려는 자기 장비(DUT)**의 IPTV 품질을 편하게 시험하려고 만든다. 판매 목적이 아니다.
- **어디서:** 인터넷과 분리된 **격리된 시험실(시험망)** 안에서, **본인이 소유·관리하거나 시험 권한이 있는 장비**만 대상으로 한다. 시험망 노드는 인터넷에 연결하지 않는다(13장 망 분리).
- **무엇을 하나:** 시험용 IPTV 트래픽을 **송신 PC가 만들어** DUT를 거쳐 수신기로 보내고, 손실·지터·재생 품질을 잰다. 실제 방송·통신사 서비스를 가로채거나 흉내 내 침입하는 것이 아니다. 트래픽은 시험망 안에서만 돈다(TTL 제한, 격리).
- **스트레스 시험의 의도(5-1):** 내 장비가 **한계 부하에서도 버티는지, 결함(손실·행·재부팅·오동작)이 나오면 어디서 나는지**를 실험실에서 찾는 **정상적인 품질 검증**이다. 남의 장비·서비스를 마비시키려는 것이 절대 아니다. 부하는 격리된 시험망 안, 내 DUT에만 건다. (근거: ISA EDSA-401 부하 스트레스 시험, RFC 3918 처리량·수용량 벤치마크 — 모두 공개된 장비 검증 표준)
- **하지 않는 것:** DUT에 로그인·침입하지 않는다(도구는 DUT를 건드리지 않음, 설계 원칙). 유일한 예외는 **본인 공유기에 명시적으로 켠 읽기 전용 DUT 모듈**(12 4-2, 로그·상태 떠 오기)뿐이다. 공유기 설정은 어떤 모듈도 바꾸지 않는다 — 처리량 시험은 측정 PC의 NIC 설정만 바꾼다(`docs/modules/throughput.md`, 2026-10-02). 인터넷으로 트래픽을 내보내지 않는다. 취약점을 악용하지 않는다. 남의 네트워크를 대상으로 하지 않는다.

## 단계
| 단계 | 내용 |
|------|------|
| **1차 (지금)** | IPTV 모듈. 시험실 한 곳, Controller 한 대. 사람 손이 필요한 일이 일부 남음(케이블, 설치 계정 입력, 태블릿 첫 허용 — 공유기 설정은 B 방식이 기본이라 없음, 07 3.2) |
| 2차 | throughput 등 모듈 추가, 외부에서 원격 지시(Claude 경유 / 로그인 웹), 시험 연속 실행(큐) |
| 2~3차 | 경험 DB 기반 추천·자동 대응, 관리자에게 메신저·이메일 보고 및 지시 받기 (`14-autonomy.md`) |
| 3차 | **사람 손이 필요한 일을 하나씩 모듈로 대체** (아래) |
| 최종 | 여러 시험실·여러 Controller를 위에서 묶어 지휘, 사람은 밖에서 지시·결과 확인만 |

## 1차부터 사람 손 최소화
> 원칙: 사람이 하는 일은 **처음 한 번만**(준비), 시험 때마다 하는 일은 **0**을 목표로 한다.

| 사람이 하던 일 | 1차에서 자동화 | 남는 사람 일 |
|----------------|----------------|--------------|
| DUT WAN에 IP 설정 | **기본값 = 송신 PC가 통신사처럼 공유기 WAN에 주소를 줌(B)** → 공유기를 공장 설정 그대로 사용(07 3.2). 공유기에서 정한 고정 IP(A)도 툴이 알아봄 | 송신 PC 처음 설치 때만 케이블 한 번 옮김(LAN에서 설치 → WAN). 옮기면 통신사 역할이 스스로 켜지고 Controller가 새 주소를 스스로 찾음(GAP-75). 옮기라는 안내는 Action Required(SND-022, WAN 쪽 PC가 생기면 스스로 닫힘, 20장 W-2) |
| 송신 PC IP 입력(NAT) | 권장·DHCP 주소 자동 시도, 등록된 송신 PC가 옮겨지면 스스로 다시 찾음(06 10.2, GAP-75) | 못 찾을 때만 1회 |
| DUT의 IGMP·M2U 상태 확인 | 사전 점검에서 멀티캐스트 전달·M2U 동작을 **자동 측정**(10-verification 4장) | 메모는 선택 |
| 수신 PC 유선↔무선 바꾸기 | 유선·무선 NIC를 모두 연결해 두고 **소프트웨어로 선택**. 무선은 DUT SSID에 자동 연결 | 처음 Wi-Fi 비밀번호 1회 |
| 태블릿 Wi-Fi를 DUT에 연결 | adb로 **자동 연결**(S-51, SSID·비밀번호는 Controller가 암호화 보관) | 처음 Wi-Fi 이름·비밀번호 1회(수신 PC와 같은 값) |
| 태블릿 앱 설치·권한·화면 켜짐 유지·절전 제외 | adb로 자동 | **USB 디버깅 허용 1회**(태블릿당 처음 한 번). 제조사에 따라 앱 설치 허용 1회(INS-018, 자동 누르기는 P5 후보) |
| 송신·수신 PC 자동 로그인 설정 | 설치 때 **자동 설정**(사용자 확인 후). Linux: SSH 설치 `--auto-login`(GDM, 제거 때 원복, 06 11.3 4-2) | 확인 1회 (GDM이 아니면 직접 켜기 1회) |
| Windows 업데이트 재부팅 방지 | 시험 기간 동안 **자동으로 업데이트 일시 중지**, 끝나면 원복 | 없음 |
| Linux Agent 설치 | Controller에서 SSH 원격 설치 | 계정 입력 1회 |
| Windows Agent 설치 | - | 설치 파일 실행 1회 |
| 멈춘 장비 재시작 | 서비스 자동 재시작, 원격 Reset All | PC 전원이 완전히 멈춘 경우만(3차: 원격 전원) |

## 사람 손 → 원격 조정으로 바꿀 대상 (3차 후보)
| 지금 사람이 하는 일 | 원격으로 바꾸는 방법 (후보) |
|---------------------|-----------------------------|
| 장비 전원 끄고 켜기, 멈춘 장비 재부팅 | 원격 전원 제어 장치(네트워크 콘센트, PDU) 모듈 |
| 공유기(DUT) 설정 변경, 펌웨어 올리기 | **하지 않는다**(2026-10-02 사용자). 공유기 설정은 사람이 정해 둔 값 그대로 두고 읽어서 보고서에 적기만 한다. 처리량 시험에서 바꾸는 것은 측정 PC의 NIC 설정뿐 |
| 공유기 로그·상태를 시험과 동시에 보기 | DUT 모듈(12-architecture 4-2): 시리얼·syslog 로그 동시 기록(2차), 사건 때 읽기 전용 상태 떠 오기(2차), 읽기 전용(공유기 설정·펌웨어는 바꾸지 않음) |
| 케이블 연결 바꾸기 | 원격 전환 스위치·USB 허브 전원 제어 |
| 태블릿 첫 허용(USB 디버깅), 화면 누르기 | 초기 준비 절차(한 번), 이후 adb로 모두 처리 |
| PC 로그인·화면 확인 | 자동 로그인(D43), 원격 화면(KVM) |

## 지금(1차)부터 지키는 원칙 — 꿈을 막지 않게
1. **모든 기능은 원격으로 부를 수 있어야 한다:** 화면에서만 되는 기능 금지. 모든 동작은 CLI·API(13-ai-loop 2장)로도 가능.
2. **사람 손이 필요한 곳은 "교체 가능한 단계"로:** 지금은 "사람에게 요청" 단계로 두되, 나중에 모듈로 바꿔 끼울 수 있게 모듈 계약(12-architecture 2장)에 맞춘다. 예: `dut.configure`, `power.cycle` 같은 단계 이름을 미리 정하고 지금은 "Ask human" 구현.
3. **사람 없이 스스로 회복:** 자동 로그인, 서비스 자동 재시작, 장애 시 안전 정지·보고, 원복 확인(F11, F13). 현장에 사람이 없다는 전제로 설계.
4. **모든 결과·사건은 원격에서 읽을 수 있게:** 보고서·진단 파일·사건 기록을 기계가 읽는 형식(JSON)으로 함께 남긴다.
5. **확장 가능한 이름 체계:** 장비·시험실 ID를 처음부터 둔다(`lab_id`, `device_id`). 지금은 시험실 하나(`lab-1`)지만 나중에 여러 곳을 묶을 수 있게.
6. **원격 연결은 "창문"일 뿐, 시험은 현장에서 스스로 돈다:** 해외에서의 연결이 느리거나 끊겨도 시험은 계속되고, 다시 연결되면 그동안의 상태·결과를 받아본다. 원격 명령은 즉시 응답을 기다리지 않는 방식(요청 → 접수 → 나중에 결과 확인)으로 만든다.
7. **멀리서도 가볍게:** 원격에서는 요약(판정, 5분 칸, 문제 목록)을 먼저 받고, 큰 파일(1초 기록, 진단 zip)은 필요할 때만.
8. **사람 손 없이 할 수 있는 것은 전부 자동으로, 아무나 할 수 있게(2026-09-26 사용자):** 툴이 알아내거나 대신할 수 있는 일은 사람에게 시키지 않는다(도구 설치, 주소 바뀜 따라가기, NIC 경로 설정. 공유기 설정은 바꾸지 않음). 남는 사람 일은 **전문 지식 없이** 화면 안내만 보고 할 수 있어야 한다(명령어·네트워크 지식을 요구하지 않음, 08 설명서 규칙). 새 기능을 만들 때 "이 단계를 사람이 해야 하나?"를 먼저 묻고, 해야 하면 00 표와 Action Required(F22)에 올린다.
9. **시간대:** 모든 기록은 UTC, 보는 사람의 현지 시각으로 표시(해외 어디서 보든 헷갈리지 않게).
10. **알림:** 시험 완료·FAIL·장애가 생기면 휴대폰으로 알림(2차: Claude 원격 세션 알림 또는 메신저·메일 연동).
