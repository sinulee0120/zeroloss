# 07. 네트워크 구성 (모든 PC를 공유기 한 대에 연결)

> 별도 관리용 네트워크는 없다. **Controller, 송신 PC, 수신 PC, 태블릿 모두 검증 대상 공유기(DUT) 한 대에 연결**한다.
> 따라서 제어 트래픽도 DUT를 지나간다. 이 문서는 그 상태에서 제어가 동작하고, 제어가 측정을 오염시키지 않게 하는 규칙을 정한다.

## 1. 연결 구성

```
                 WAN 포트                        LAN 포트 / Wi-Fi
[송신 PC] ─────────────┐                 ┌──────── [Controller PC] (LAN 유선)
 (WAN 쪽 IP)           │                 ├──────── [수신 PC] (LAN 유선 또는 Wi-Fi)
                       └──[ DUT 공유기 ]──┤
                                         └~~Wi-Fi~~ [태블릿 1~3] ──USB── [수신 PC]
```

| 장비 | 연결 위치 | IP 대역 |
|------|-----------|---------|
| 송신 PC | DUT **WAN** 포트 | WAN 쪽 대역 (예: 10.0.0.0/24) |
| Controller PC | DUT **LAN** 포트 (유선) | LAN 쪽 대역 (예: 192.168.1.0/24, DUT DHCP) |
| 수신 PC | DUT LAN 포트 또는 Wi-Fi | LAN 쪽 대역 |
| 태블릿 | DUT Wi-Fi (영상 수신), 수신 PC와 USB (제어·보고) | LAN 쪽 대역 |

- **시험에 안 쓰는 무선 NIC(2026-09-26 사용자, 20장 GAP-88): 상관없으면 켜 둔다.** 송신 PC처럼 무선이 필요 없는 노드의 Wi-Fi(다른 공유기로 인터넷에 붙어 있을 수 있음)는 기본으로 그대로 둔다(유선 시험에는 영향 없음, 개발 중 인터넷 필요). **DUT 무선을 쓰는 시험**(태블릿·무선 수신 PC)에서 그 Wi-Fi가 DUT와 **같은 대역**(2.4 GHz / 5 GHz / 6 GHz)이면 전파 간섭이 되므로, Start 때 노드가 그 연결만 내리고(NetworkManager) 시험이 끝나면(정상·안전 정지·Reset All 모두) 원래대로 켠다. 끌 때·켤 때 사건 기록. Controller PC는 인터넷이 필요하므로 끄지 않고 같은 대역이면 사전 점검 ⚠(13 1). 무선으로 받는 수신 PC의 Wi-Fi는 시험 NIC라 끄지 않는다.
- Controller는 **LAN 쪽 유선**에 연결한다(무선 금지). 외부(인터넷)용 NIC를 하나 더 두며, 두 망은 절대 잇지 않는다(`13-ai-loop.md` 1장). 제어가 시험 중인 무선 구간을 쓰지 않게 하기 위해서다.

## 2. NAT 모드와 Bridge 모드에서 IP가 달라지는 점

| 항목 | NAT 모드 | Bridge 모드 |
|------|----------|-------------|
| WAN 쪽과 LAN 쪽 대역 | **다름** (DUT가 주소 변환) | 같은 대역 (DUT가 그냥 연결만) |
| Controller → 송신 PC 연결 | LAN→WAN 방향이라 NAT를 거쳐 **연결 가능** | 바로 연결 |
| 송신 PC가 보는 Controller 주소 | **DUT의 WAN IP** (Controller 실제 IP가 아님) | Controller 실제 IP |
| 송신 PC → Controller 방향 새 연결 | **불가** (NAT가 막음) | 가능 |
| 방송 발견(UDP) | LAN 쪽만 닿음. **송신 PC는 방송으로 못 찾음** | 전체에 닿음 |
| 멀티캐스트 경로 | DUT의 IGMP Proxy(RFC 4605)가 WAN으로 Join을 올리고 LAN으로 내려줌 | IGMP Snooping(RFC 4541) 여부에 따라 전달 |
| IP 할당 | LAN·WLAN: 보통 **공유기 DHCP**(흔히 192.168.1.x, 192.168.45.x 등 — 공유기마다 다름), 장비에서 고정 IP로 넣는 경우도 있음(2026-09-26 사용자) / WAN: 아래 3장 | 시험 PC에 고정 IP 필요 (DUT가 DHCP를 안 할 수 있음) |

## 3. WAN 쪽 IP 설정 (두 방식 모두 지원)
실험실에는 통신사망이 없으므로 **송신 PC가 통신사 역할**을 한다. DUT WAN과 송신 PC는 같은 대역이어야 한다. **기본값은 B(송신 PC가 통신사처럼 주소를 줌)** — 공유기를 건드리지 않아 사람 손이 필요 없다(`00-vision.md`). A(공유기에서 정한 고정 IP)도 그대로 되고, 어느 쪽인지는 툴이 알아본다(3.3). 사람이 방식을 고를 필요는 없다(S-17은 기본값 기록용).

| | A. 고정 IP | B. 송신 PC가 DHCP 서버 |
|---|-----------|------------------------|
| 하는 일 | 사람이 DUT WAN과 송신 PC에 고정 IP를 넣는다 | 송신 Agent가 WAN 포트에서 DHCP 서버가 되어 DUT WAN에 IP를 준다 |
| DUT 설정 | WAN을 고정 IP로 바꿔야 함 | **DUT 기본 설정(DHCP) 그대로** |
| 실제 통신사 환경과 | 다름 | 가까움 |
| 기본 권장 값 | DUT WAN 10.0.0.1/24, 송신 PC 10.0.0.2/24 | 송신 PC 10.0.0.1/24(게이트웨이), DUT에 10.0.0.100 할당 |

### 3.1 A. 고정 IP
- Controller 화면에 권장 값을 보여주고, 사용자가 DUT와 송신 PC에 입력한다.
- 사전 점검: 송신 PC에서 DUT WAN IP로 도달 확인, 같은 대역인지 확인.

### 3.2 B. 송신 PC가 통신사처럼 WAN 주소를 줌 (기본, 2026-09-26 다시 정함, 20장 GAP-60)
- **ZeroLoss 내장 DHCP 서버**(Windows·Linux 공통, 외부 프로그램 불필요, `core/blocks/dhcp_server.py`)를 **송신 PC 노드가 스스로** 돌린다. 사용자는 공유기 WAN을 공장 설정(DHCP로 받기) 그대로 두면 되고 **손으로 할 일이 없다.**
- **왜 노드가 스스로 하나(순서 모순을 고침):** NAT 모드에서 LAN 쪽 Controller는 공유기 WAN에 주소가 있어야만 WAN 쪽 송신 PC에 닿는다. 그 주소를 주는 것이 이 DHCP라, Controller가 시험 때 켜 줄 수 없다. 전에는 "시험 때 켜고 끝나면 끄고 NIC 주소를 되돌림"이었는데, 되돌리면 그 순간부터 송신 PC에 못 닿는다. → **노드가 켜질 때마다 준비하고 늘 켜 둔다. 되돌리는 것은 WAN 역할을 끌 때와 노드를 제거할 때만.**
- **WAN 역할은 스스로 켜진다(2026-09-26 사용자 "그냥 알아서 되게", 20장 GAP-75):** 사용자는 명령을 몰라도 된다. 노드 설정(`agent.json` `wan_isp.on`)이 없으면 **자동**(`auto`, 기본): 노드가 10초마다 보고, **유선 NIC 하나가 링크가 올라온 채 20초 넘게 IPv4 주소가 없고(169.254.x만 있어도 없음으로 봄) 그 NIC에 DHCPDISCOVER(3초)를 보내도 아무 서버도 답하지 않으면** 그 NIC가 공유기 WAN 포트라고 보고, **마지막으로 10.0.0.1이 비었는지 ARP로 확인(RFC 5227 탐색)한 뒤 곧바로** 역할을 켠다. 다른 PC가 그 주소를 쓰거나 **같은 순간에 같은 주소를 묻고 있으면**(DHCP 없는 한 망에 PC 둘, 예: Bridge 모드 공유기·스위치) 켜지 않고 무작위(0~20초) 뒤 다시 본다 — 두 PC가 함께 10.0.0.1을 붙이지 않게(GAP-76 ⑤). ARP 확인을 못 하면(권한 없음) 자동으로 켜지 않는다(공유기 WAN은 주소를 기다리고, 공유기 LAN은 주소를 준다). DHCP 서버가 답하는 곳(공유기 LAN 등)은 조용히 그대로 둔다. **Controller 역할 PC에서는 자동으로 켜지 않는다**(지금처럼 수신과 한 PC여도, 나중에 Windows Controller로 나눠도 같음 — Controller PC의 NIC는 건드리지 않음). 켜진 뒤 그 NIC의 링크가 끊기면 바로 응답을 멈추고, 다시 올라오면 다른 DHCP 서버가 있는지 먼저 묻는다 — 자동이면 답이 있을 때(공유기 LAN으로 옮김) 더한 주소를 빼고 역할을 끈다(한 망에 DHCP 서버 둘 금지). 사람이 정할 수도 있다: `zeroloss devices wan <이름> --on|--off|--auto`(02 4 `POST /v1/wan`, `--auto` = 다시 자동). 이 역할이 켜진 PC에서만 NIC를 건드린다(다른 PC의 NIC는 절대 안 건드림).
- **처음 설치(2026-09-26 사용자 결정):** 송신 PC를 **처음 한 번만 공유기 LAN 포트(또는 Controller와 같은 망)에 꽂아** 설치하고(SSH 설치, 06 11.3) WAN 포트로 옮긴다 — 역할은 옮기면 스스로 켜지고(위), Controller는 등록 주소가 답하지 않으면 스스로 다시 찾아 새 주소(10.0.0.1)를 저장한다(06 10.2, GAP-73 ④). 설명서 한 단계 + Action Required(F22 `human.cable.move_sender_to_wan`, SND-022): 자동 역할이면 Controller가 공유기 WAN 쪽 PC가 없을 때 한 번 열고 WAN 쪽 PC가 생기면 스스로 닫는다(20장 W-2), 손으로 켠(`--on`) 역할이면 송신 노드가 연다. 그다음부터 사람 할 일 없음.
- **WAN NIC 고르기(자동, 사용자 결정):** 링크가 올라왔고 IPv4 주소가 없는 **유선 NIC가 딱 하나**면 그것. 둘 이상이면 아무것도 바꾸지 않고 DSC-006 → Action Required "Choose the network card that goes to the router WAN"에 **카드마다 버튼**(이름·링크 속도·MAC, 2026-09-26 사용자 결정 20장 W-1). 누르면 `zeroloss devices wan <이름> --nic <카드>`와 같다(CLI `zeroloss actions choose <key> <카드>`). 이미 주소가 있는 NIC(사람이 고정 IP를 넣은 경우 = A 방식)는 고르지 않는다.
- **주소는 카드에서 확인한다(2026-10-02 첫 실기, 20장 GAP-98):** "이미 붙였다"는 임대 기록 파일이 아니라 **그 카드에 실제로 10.0.0.1이 있는지**로 판단한다(재시작 뒤 파일만 남고 주소가 없으면 다시 붙임). 역할이 `ready`인 동안에도 몇 초마다 주소를 확인해, 다른 프로그램(그 카드의 NetworkManager 기본 프로필 "Wired connection 1"이 DHCP를 계속 다시 시도하며 주소를 지움 — 첫 실기에서 24시간 720번)이 지우면 다시 붙이고 SND-023 ⚠. 10분에 세 번 넘게 지워지면 역할을 멈추고 SND-023 ✖(무엇이 지우는지와 끄는 방법 안내).
- 동작 범위를 좁게 제한한다:
  - 고른 **WAN NIC 한 개에서만** 동작한다(Linux `SO_BINDTODEVICE`). 다른 NIC에서는 절대 응답하지 않는다.
  - 송신 PC의 그 NIC에 **10.0.0.1/24를 더한다**(원래 설정을 지우지 않고 추가만, 뺄 때도 우리가 더한 것만).
  - 주소는 **1개만** 빌려준다(DUT용, 기본 10.0.0.100). 임대 시간 7일, 갱신이면 같은 주소. 임대 기록은 노드 데이터 폴더(`wan-lease.json`)에 두어 재시작해도 같은 주소.
  - **케이블을 다른 장비로 옮기면 주소도 따라간다**(2026-10-04 기준선 시험, 20장 GAP-112): 임대 중인데 **다른 MAC**이 주소를 청하면(DISCOVER·REQUEST) 송신 노드가 그 카드에서 10.0.0.100이 아직 ARP에 답하는지 확인한다(RFC 2131 4.4.1 "주기 전에 확인", 확인은 10초에 한 번, 그동안 답하지 않음). **아무도 답하지 않으면** 다음 요청에 새 MAC에게 주고 "Router WAN address moved from <옛 MAC> to <새 MAC>"(INFO). **옛 장비가 답하면** 주지 않고 SND-024. 확인할 수 없으면(패킷 소켓 없음) 주지 않고 SND-024(이유 표시) — 확인 없이 옮기면 두 장비가 같은 주소를 쓴다. 공유기 → 기준선의 수신 PC, 수신 PC → 공유기 두 방향 모두 사람 손·sudo 없이.
  - 게이트웨이는 송신 PC(10.0.0.1), DNS는 주지 않는다.
- **충돌 방지:** 시작 전에 그 NIC 쪽에 다른 DHCP 서버가 있는지 한 번 물어보고(DHCPDISCOVER, 3초), 답이 오면 시작하지 않고 SND-012.
- DUT가 IP를 받아 가면 그 주소를 기록하고(`GET /v1/wan`), Controller는 NAT 판별(4장)로 같은 값을 확인한다. 60초 안에 요청이 없고 임대 기록도 없으면 SND-011 ⚠(공유기 WAN이 DHCP인지 확인 안내).
- 기록: DHCP 요청·응답 시각과 할당 주소를 노드 사건으로 남긴다. 시험 중 DUT가 다시 요청하면(재부팅 등) 이벤트(NET-001 원인 후보).

### 3.3 공통
- **왜 두 방식인가(2026-09-26 사용자 확인, 20장 GAP-60):** 실험실은 통신사망이 없는 **폐쇄 루프**라 NAT 모드의 공유기 WAN IP를 통신사에게 받지 못한다. 사람이 공유기에서 임의로 정해도 되고(A), **진짜 통신사처럼 송신 PC가 자동으로 주면(B) 사용자가 공유기를 건드리지 않아 더 편하다** → B 기본, A도 그대로 지원. LAN·WLAN 쪽 DHCP는 언제나 **공유기 자체 것**이다(ZeroLoss의 DHCP는 WAN 포트 쪽 한 NIC·한 주소만).
- **어느 방식이 쓰이는지 툴이 알아본다:** S-17이 Built-in DHCP여도, 공유기 WAN이 이미 고정 IP로 송신 PC 대역에 있으면(NAT 판별의 공유기 WAN IP가 우리 임대가 아님) 그 IP를 그대로 쓰고 "Router WAN is static"을 체크리스트에 적는다(오류 아님). 공유기가 DHCP로 WAN을 요청하면 우리가 준다.
- **LAN·WLAN 쪽은 대역을 가정하지 않는다:** 공유기 DHCP 대역이나 사람이 넣은 고정 IP 어느 쪽이든 쓴다. 장비는 방송 발견(06 10.2)으로 찾고, DHCP로 IP가 바뀌어도 `device_id`로 같은 장비를 알아본다(DSC-004).
- **송신 PC의 IP는 DUT WAN과 같은 대역이어야 한다.** 멀티캐스트 발신 주소가 WAN 대역 밖이면 DUT가 역경로 검사(RPF)로 버릴 수 있다. 사전 점검에서 확인한다.
- 선택한 방식과 사용한 IP 값은 보고서에 기록한다.

## 4. NAT 자동 판별 (사용자 입력 최소화)
Controller는 송신 PC에 처음 연결할 때 다음을 자동으로 알아낸다.
1. 송신 Agent가 "나에게 들어온 연결의 출발 주소"를 알려준다.
2. 그 주소가 Controller 자신의 IP와 **다르면 → NAT 모드**이고, 그 주소가 **DUT의 WAN IP**다.
3. 같으면 → Bridge(또는 NAT 없음) 모드다.
4. 판별 결과(모드, DUT WAN IP, DUT LAN IP = Controller의 기본 게이트웨이)를 화면에 표시하고 보고서(`dut.mode_detected`)에 기록한다. 사용자에게 모드를 묻지 않으므로 비교할 값도 없다(DSC-007 쓰지 않음, 20장 W-5).

## 5. 장비 찾기 (모드별)
| 대상 | NAT 모드 | Bridge 모드 |
|------|----------|-------------|
| 수신 PC | 방송 발견 (LAN 쪽) | 방송 발견 |
| 송신 PC | 먼저 **권장 주소를 자동 시도**(DHCP 방식 10.0.0.1, 고정 IP 방식 10.0.0.2). 등록된 송신 PC가 답하지 않으면 스스로 다시 찾아 새 주소를 저장(06 10.2, GAP-75). 그래도 못 찾으면 **IP를 한 번 입력**(송신 PC 화면/트레이에 "My IP" 표시). 이후 저장 | 방송 발견 |
| 태블릿 | 수신 PC의 USB(adb) 목록 | 같음 |

## 6. 제어 연결 규칙 (NAT를 통과하도록)
- **모든 제어 연결은 Controller가 먼저 연다** (Controller → Agent). Agent는 Controller로 새 연결을 열지 않는다.
  - heartbeat: Controller가 1초마다 요청
  - 1초 핵심값, 5분 요약: Controller가 가져간다(pull). 수신기는 준비해 두고 기다린다. 받지 못한 요약은 수신기에 보관했다가 다음 요청 때 함께 준다.
- **접근 허용 (기본: 키 없음):** 빌드할 때마다 키를 관리하는 번거로움을 없애기 위해 **기본값은 키 서명 없이** 동작한다.
  - 기본 보호: 방화벽 범위를 좁힌다. LAN 쪽 Agent는 Controller IP만, WAN 쪽 송신 Agent는 DUT WAN IP만 허용(NAT 모드에서는 송신 PC에 Controller가 DUT WAN IP로 보이기 때문). 판별 결과로 자동 설정.
  - **선택 옵션: 페어링 키 서명(HMAC).** 켜면 모든 요청에 서명을 붙이고 틀린 요청을 거부한다. 공유 네트워크에서 쓰거나 공개 배포할 때 켜는 것을 권장한다. 키는 Controller가 페어링 때 자동으로 만들어 나눠 주므로 빌드와는 무관하다.

### 6-1. LAN 쪽 PC가 WAN 쪽 송신 PC에 닿는 길 — 공유기가 바뀌어도 사람 일 없음 (2026-10-15, 20장 GAP-158)
- 사용자: "공유기가 이렇게 바뀔때마다 10.0.0.1을 192.168.1.1로 바꾸는건 AI없으면 불가능한거네?", "공유기 10대씩 다양한거 테스트할땐 어쩌라는거야".
- 수신 PC의 프라임(iptv 4.5)과 처리량 클라이언트(iperf3 -c)는 송신 PC의 WAN 주소(10.0.0.x)로 보낸다. 그 PC의 기본 경로는 흔히 자기 인터넷(집 Wi-Fi)이라 패킷이 엉뚱한 카드로 나갔고, PC 프로필에 손으로 넣은 고정 경로는 공유기가 바뀌면 죽었다.
- **시작할 때마다 노드가 스스로:** 송신 주소로 가는 길이 이미 시험 카드로 나가면 아무것도 안 함. 아니면 그 카드가 **지금 꽂힌 공유기의 게이트웨이**(NetworkManager의 IP4.GATEWAY, 없으면 DHCP `routers`)로 송신 주소의 /24 경로를 **런타임에만** 더한다(`nmcli device modify <카드> +ipv4.routes`, PC 설정에 저장 안 함). 노드가 IDLE로 돌아가면 그 경로를 뺀다. 못 만들면 NET-023(경고, 시험은 계속).
- 앱은 PC의 **저장된** 네트워크 설정(프로필·Wi-Fi 켜고 끄기)을 바꾸지 않는다. 사람에게 Wi-Fi를 끄거나 네트워크를 지우라고 하지도 않는다(GAP-155 NET-018).

## 7. 제어 트래픽이 측정을 오염시키지 않게
제어가 DUT를 지나가므로 다음을 지킨다.
- **양을 최소화:** heartbeat는 수백 바이트, 1초 핵심값은 수십 바이트. 5분 요약은 수 KB. 1초 원본 기록과 화면 캡처는 **시험 종료 후** 회수(시험 중에는 필요할 때만 저해상도 캡처).
- **무선 수신 PC:** 시험 중 제어도 Wi-Fi로 다니게 된다. 영상(최대 40 Mbps/채널) 대비 제어는 1초당 수 KB 이하로 제한하고, 실제 제어 트래픽 양을 기록해 보고서에 표시한다. (선택: 유선 NIC가 따로 있으면 제어는 유선으로)
- **태블릿:** 제어·보고는 USB(adb)만 쓴다. Wi-Fi로는 영상만 받는다.
- **발견(방송·스캔)은 시험 중 금지.**
- 보고서에 장비별 제어 트래픽 양(평균·최대 bps)을 적는다.
- **결과 조회 웹(TCP 10993):** 시험 중에 DUT의 Wi-Fi에 연결된 휴대폰·PC로 결과 웹을 보면 그 트래픽이 시험 중인 무선 구간을 지나간다. 시험 중 조회는 **유선 장비에서만** 하도록 화면과 설명서에 안내하고, 조회 트래픽 양도 기록한다.
- **태블릿 시험 중 수신 PC**는 영상을 받지 않는다(태블릿 중계만).

## 8. 사전 점검 (시험 시작 전 자동)
- [ ] Controller가 LAN 쪽 유선에 연결됨
- [ ] 시험 PC가 시험망 밖으로 연결돼 있지 않음: Controller가 Wi-Fi 카드로 닿지 않음(무선 수신 PC의 시험 카드 제외), 통신사 역할 송신 PC는 NAT를 거쳐 닿음, 시험에 안 쓰는 Wi-Fi에 주소 없음 — 아니면 ⚠ NET-018(시작은 허용, 20장 W-3). Controller PC 자신은 제외
- [ ] 송신 PC IP가 DUT WAN과 같은 대역
- [ ] 공유기 WAN 주소 방식 확인: B면 통신사 역할 `ready`이고 공유기 WAN이 그 주소를 받음(`dut.wan_ip_way: dhcp`), A면 `static`(07 3.3). 다른 DHCP 서버는 통신사 역할을 켤 때 이미 확인(SND-012)
- [ ] NAT 판별 결과 기록(`dut.mode_detected`) — 묻지 않으므로 비교 없음(20장 W-5)
- [ ] 송신 PC → 수신 쪽으로 멀티캐스트 시험 패킷(짧은 1~2초)이 실제로 도달 (TTL 확인 포함)
- [ ] 모든 Agent heartbeat 정상 (키 옵션을 켰다면 키 확인)
