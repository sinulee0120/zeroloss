# 11. 화면(UI) 설계와 UI 문제 예방

> 실시간 IPTV 도구는 예외가 많고, 그 예외가 **화면에서 문제로 드러난다**(멈춤, 틀린 표시, 팝업 폭탄, 버튼 상태 꼬임).
> 이 문서는 ① UI 구조 규칙 ② 화면 목록과 배치 ③ 흔한 UI 문제와 예방책 ④ UI 시험 방법을 정한다.
> 화면 기능 정의는 `03-features.md`(F12~F21), 이 문서는 **어떻게 만들지**를 정한다.

## 1. UI 구조 규칙 (Controller, PySide6)

### 1.1 상태는 한 곳에만 (Single source of truth)
- 상태 저장소는 **Controller 노드 서비스 안에 하나**(12-architecture 1-0). 화면 앱(Controller Desktop)은 10994 이벤트 스트림으로 받은 **사본**을 그린다. 연결이 끊기면 화면 전체를 "Reconnecting…"으로 잠그고 다시 붙으면 전체 상태를 새로 받는다. 저장소 내용: 시험 상태, 장비 목록·연결 상태, 1초 값, 5분 칸, 문제 목록, 설정.
- 화면은 **상태 저장소만 보고 그린다.** 버튼·라벨이 자기만의 변수(예: `is_running` 플래그)를 따로 갖지 않는다.
- 상태를 바꾸는 방법은 **명령 → 처리 → 상태 저장소 갱신** 하나뿐. 화면은 결과를 따라 바뀐다.
- 효과: "버튼은 Stop인데 실제로는 멈춤" 같은 **표시와 실제의 불일치**가 구조적으로 생기지 않는다.

### 1.2 화면 스레드를 절대 막지 않는다
- 네트워크, 파일, adb, 외부 프로그램, 보고서 생성은 전부 **백그라운드 작업자**에서. 화면 스레드는 그리기만 한다.
- 개발용 감시: 화면 스레드가 **200 ms 넘게 멈추면** 로그에 경고(어느 함수에서 멈췄는지). 시험에서 0건이어야 한다.

### 1.3 갱신은 묶어서, 최대 1초에 1번
- 장비 여러 대 × 1초 값이 와도, 화면 갱신은 **1초에 한 번 모아서** 한다.
- 긴 목록(1초 값 1,000줄, 문제 목록, 보고서 목록)은 **가상 목록**(보이는 줄만 그리는 모델-뷰 방식)으로 만든다. 줄마다 위젯을 만들지 않는다.
- 그래프는 화면 폭 이상의 점을 그리지 않는다(구간이 길면 요약값으로 줄여서 그림).

### 1.4 100시간 동안 화면 메모리가 늘지 않게
- 화면이 들고 있는 자료는 **정해진 크기의 순환 버퍼**(1초 값 1,000줄, 그래프 점 N개). 오래된 것은 버리고 필요하면 파일에서 다시 읽는다.
- 창을 열고 닫을 때 만든 객체를 확실히 정리(해제)한다. 100시간 화면 메모리 증가 시험(SYS-002)에 UI 포함.

### 1.5 오래된 값을 새 값처럼 보여주지 않는다
- 모든 실시간 값 옆에 **갱신 상태**를 둔다. 3초 넘게 새 값이 없으면 회색 글씨 + "Last update 12 s ago". 연결이 끊긴 장비의 값을 계속 초록으로 보여주지 않는다.

### 1.6 팝업은 최소, 하나씩
- **작업을 막는 팝업(모달)은 판단이 꼭 필요한 경우만:** Stop 확인, 시험 중 창 닫기 확인, 제거 확인, 결과 보기(F15).
- 나머지 알림은 **Problems 창과 배지(F21)**로. 같은 문제로 팝업이 여러 번 뜨지 않는다.
- 모달은 **동시에 하나만.** 여러 개가 필요하면 차례로(대기열).

### 1.7 문구·색·아이콘은 한 곳에서
- 화면 문구(영어)는 **문구 파일 하나**에 모은다. 코드에 문장을 흩어 적지 않는다(나중에 한국어판도 이 파일만 바꾸면 됨).
- 색·아이콘도 한 곳에서 정의: 초록 ✔, 노랑 △, 빨강 ✖, 보라 ◆, 회색 ○. **색만으로 구분하지 않고 항상 아이콘을 함께**(색약 사용자).
  - **노랑 = 참고(2026-10-03 사용자, 20장 GAP-106):** 노랑은 판정을 바꾸지 않는 참고 사항(PASS 그대로)이므로 느낌표 경고 표시(⚠)를 쓰지 않는다 — PASS인데 ⚠가 보이면 실패처럼 읽힌다. 속 빈 삼각형 △(나머지 넷과 모양이 다름, 흑백 구분 유지). 정의는 `core/ui_schema/design.py` `ICONS` 하나뿐이고 보고서(`controller/report.py`·`report_page.py`)·결과 웹(`controller/web.py`)도 그것을 쓴다. 시작 전 점검의 ⚠(사람이 볼 것)·`⚠ Storage low` 같은 주의 표시는 칸 색이 아니므로 그대로.
  - **5분 칸에도 적용(2026-09-24 결정):** 실시간 화면·보고서의 모든 칸에 아이콘을 함께 그린다(칸이 작으면 칸 안 아이콘, 더 작으면 툴팁 + 흑백에서도 구분되는 무늬). 7장 "흑백 시험"으로 확인.
  - **정상 칸의 진하기(2026-09-24 결정, ISA-101):** 시험 중 **실시간 화면**의 초록 칸은 채도 낮은 연한 초록으로 둬서 노랑·빨강·보라가 눈에 띄게 한다. **보고서**는 판정 문서이므로 지금처럼 분명한 초록. 두 값 모두 디자인 값 파일 하나에서 정의.
- 오류 표시는 공통 부품 하나(What / Why / Fix / 버튼)를 모든 화면에서 재사용.

### 1.7-1 용어 구분 규칙 (헷갈리는 말 금지)
> 시안 검토에서 발견: "해상도"가 **모니터 크기**인지 **보내는 영상의 크기**인지 헷갈림. 같은 말을 두 뜻으로 쓰지 않는다.

| 뜻 | 화면·보고서·설명서에 쓰는 말 | 쓰지 않는 말 |
|----|------------------------------|--------------|
| 송출 영상의 화질 | **Video quality** (예: `UHD · 3840×2160 · 35 Mbps`) | Resolution, Quality(단독) |
| 송출 영상의 가로×세로 | **Video resolution** | Resolution(단독) |
| 모니터·창의 크기 | **Screen size**, **Monitor** (예: `Monitor 1920×1080 · 125%`) | Resolution(단독) |
| 화면 배율 | **Display scale** (%) | Zoom |
| 공유기 | **Router** (보고서 기술 항목에서만 DUT 병기) | DUT(화면 문구 단독) |
| 무선 채널 | **Wi-Fi channel**, 줄에서는 `Wi-Fi 36 · 80 MHz` | Channel(단독) |
| IPTV 채널 | **CH1**, **TV channel** | Channel(단독) |
| 수신 장비 | **Receiver** (Tablet-1, Receiver PC) | Client, STB |
| 송신 장비 | **Sender** | Server, Streamer |

- 화질 선택 목록에는 **이름·해상도·비트레이트를 함께** 표시한다: `UHD · 3840×2160 · 35 Mbps`, `HD · 1920×1080 · 10 Mbps`. 이름만(`UHD`) 쓰지 않는다.
- "Resolution"이라는 말을 단독으로 쓰지 않는다. 항상 Video 또는 Screen을 붙인다.
- 이 표는 문구 파일(1.7)의 용어 목록으로 코드에 들어가고, 자동 검사로 문구 파일에 금지 단어(`Resolution` 단독 등)가 없는지 확인한다.
- 보고서·설명서·CLI 출력·오류 문구 모두 같은 용어를 쓴다.

### 1.8 해상도·배율 (어떤 컴퓨터에서도 맞게)
> 흔한 문제: 개발 PC에서는 괜찮은데 다른 컴퓨터(작은 노트북, 4K 모니터, 배율 150%)에서 화면이 잘리거나 넘치거나 너무 작게 나옴.

- **"실제로 쓸 수 있는 크기" 기준으로 설계:** 화면 해상도 ÷ 배율 **− 작업 표시줄(48 px, 2026-10-02 GAP-95)**. 예: 1920×1080 + 150% = 1280×720 → 창은 1280×672, 1366×768 + 125% = 1093×614 → 창은 1093×566(최소 600보다 낮아 안내 + 일부 스크롤).
- **기준 크기:**
  - **표준 배치:** 실제 크기 1280×720 이상 → 메인 화면이 스크롤 없이 모두 보임.
  - **좁은 배치(자동 전환):** 1280×720 미만 → 영역을 위아래로 쌓고(Test 위, Devices 아래) 필요한 곳만 스크롤. 핵심(Start/Stop, Jitter·Loss, 문제 배지)은 **항상 화면에 고정**.
  - 최소 지원: 실제 1024×600. 그보다 작으면 "Screen too small, some parts need scrolling" 안내(위쪽 막대 바로 아래). 이때는 **화면 전체가 스크롤**되고 창은 화면 안에 맞는다. Start/Stop과 안내는 처음 보이는 곳에 있다(문제 배지는 오른쪽으로 스크롤할 수 있음). 1024×600 이상에서는 화면 전체 스크롤바가 생기지 않는다.
  - **모자라면 늘리지 않고 스크롤(2026-10-02 GAP-95):** Test 영역·결함 상자(S6)·장비 영역은 각자 스크롤되어, 어느 크기에서도 창의 최소 크기가 화면보다 커지지 않는다. 결함 상자는 창 높이의 1/3까지. 화면을 다시 그리는 동안에는 배치를 멈췄다가 한 번에 계산한다(옛 버튼과 새 버튼이 잠깐 함께 보여 창이 커진 뒤 줄지 않는 문제 방지).
- **배율:** 100 / 125 / 150 / 175 / 200% 모두 지원. 소수 배율을 반올림하지 않고 그대로 적용(Qt 고해상도 설정)해 흐림·잘림 방지.
- **모니터 간 이동:** 배율이 다른 모니터로 창을 옮기면 **그 모니터 배율로 다시 그린다**(모니터별 배율 대응).
- **창 크기·위치 저장**, 다음 실행 때 모니터 구성이 바뀌어 화면 밖이면 기본 위치·크기로. 최대화 상태도 기억.
- **Agent Desktop 상태 창:** 화면 구석 기준 위치(오른쪽 아래) + 배율 반영. 작업 표시줄을 가리지 않음.
- **태블릿 앱:** 크기 단위는 dp/sp(기기 밀도 자동 반영), 가로·세로·분할 화면 모두 배치 정의. 작은 화면은 상태 표시를 접힌 상태로.
- **보고서(HTML)·결과 웹:** 반응형(휴대폰 폭 360 px ~ 4K). 좁으면 표를 가로 스크롤, 5분 칸은 줄바꿈.

### 1.9 시험 중 잠금
- 시험 중 바꾸면 안 되는 설정은 **잠그고**(회색 + 툴팁 "Locked during test"), 바꿀 수 있는 것(채널 전환, Snapshot, 구간 보기)만 열어 둔다(RUN-007).

### 1.10 버튼·체크박스 활성 상태는 표 하나로 정한다
> 흔한 문제: 버튼이 실제 동작 흐름과 맞지 않게 켜지거나 꺼짐, 체크박스·설정과 실제 동작이 따로 놂.

- 모든 조작 요소의 **활성/비활성/숨김**은 아래 "조작 상태표" **하나**에서 정한다. 코드 곳곳에서 `setEnabled()`를 따로 부르지 않는다.
  - 구현: `(시험 상태, 설정 값) → 각 요소의 상태`를 계산하는 **함수 하나**. 상태 저장소가 바뀔 때마다 이 함수로 전체를 다시 계산해 적용한다.
- 체크박스·선택 값은 **설정 저장소의 값을 그대로 보여줄 뿐**이다. 화면에서 바꾸면 → 설정 저장소 갱신 → 그 값에 따라 동작과 화면이 함께 바뀐다. 화면에 보이는 값과 실제로 쓰이는 값이 다를 수 없다.
- 시험 시작 시 설정을 **복사해 고정(snapshot)**하고, 시험은 그 복사본으로 동작한다. 보고서에도 그 값을 적는다. 화면 표시도 시험 중에는 고정된 값을 보여준다.
- 비활성 요소에는 **왜 비활성인지** 툴팁을 단다(예: "Stop the test first", "Select at least one tablet").
- **ⓘ 도움말은 입력 칸 자체에도 늘 있다(2026-09-27, 20장 GAP-84):** 입력·설정 칸(선택 상자·체크박스·숫자 칸)의 툴팁 = 도움말(무엇을 넣는지·예시·어디서 확인). 회색이면 **이유가 첫 줄, 도움말이 다음 줄** — 상태표 함수가 도움말을 지우지 않는다. 옆 이름표의 ⓘ에도 같은 도움말. 자동 시험이 화면의 모든 입력 칸을 돈다.

### 1.11 보기 좋고 깔끔하게 (디자인 규칙)
> 흔한 문제: 글자가 틀 밖으로 나가거나 겹침, 렌더링이 흐림, 버튼이 여기저기 흩어져 조잡함, 설정 화면이 난잡함.

**배치**
- 절대 좌표 배치 금지. 모든 화면은 **레이아웃(격자·행·열)**으로 만들어 창 크기·배율이 바뀌어도 자동 정렬.
- 간격은 **8 px 격자**(8, 16, 24)만 쓴다. 요소마다 제각각 여백을 주지 않는다.
- 한 화면에 **주 버튼(Primary)은 하나**(메인은 Start/Stop). 크고 색이 있다. 나머지 버튼은 보조 모양(테두리만).
- 버튼 위치 규칙 고정: 화면 전체 동작은 **오른쪽 위**(Reports, Last report), 영역 동작은 **그 영역 오른쪽 아래**, 창 확인·취소는 **오른쪽 아래(확인이 오른쪽 끝)**. 모든 화면 같게.
- 관련된 것끼리 **묶음(그룹 상자)**으로. 묶음 제목은 짧게(Test, Devices, 5-min results, Status).
- 설정 화면은 **한 열**, 라벨 왼쪽 정렬·입력칸 폭 통일, 항목 사이 간격 일정. 묶음당 항목 7개 이하, 넘치면 묶음을 나눈다.
- 드물게 쓰는 것은 숨긴다(Advanced 체크박스, [Show details], 펼치기 ▸).

**글자**
- 글꼴 한 종류(Windows 기본 UI 글꼴), 크기는 **3단계만**: 본문 / 제목 / 핵심 값(Jitter·Loss 크게).
- 숫자는 **자리 폭이 같은 숫자 글꼴(tabular)**로. 값이 바뀔 때 글자가 좌우로 흔들리지 않게. 단위는 값 옆 작은 글씨(ms, Mbps).
- 글자가 들어가는 칸은 고정 크기로 만들지 않는다. 넘치면 **말줄임(…) + 툴팁 전체 문구**. 글자가 틀을 넘거나 다른 글자와 겹치면 안 된다.
- 가장 긴 문구(영어 기준 + 여유 30%)로 칸 크기를 시험한다(나중에 다른 언어 대비).

**렌더링**
- 아이콘은 **벡터(SVG)** — 배율 150%·4K에서도 선명. 비트맵 아이콘을 늘려 쓰지 않는다.
- 고해상도 배율 대응을 켠다(HiDPI). 그래프·그리드도 배율에 맞춰 선 두께·글자 크기 조정.
- **글자와 배경 대비(안 보이는 글자 금지):**
  - 모든 글자는 배경 대비 **4.5:1 이상**(WCAG AA), 큰 글자·아이콘은 3:1 이상. **비활성(회색) 글자도 3:1 이상** — 회색이라도 읽을 수 있어야 한다.
  - 디자인 값 파일의 **모든 글자색 × 배경색 조합의 대비를 자동 계산**해서, 기준 미달 조합은 빌드에서 실패시킨다.
  - 색 배경(초록·노랑·빨강·보라 칸) 위 글자도 조합별로 확인(예: 노랑 위 흰 글자 금지).
  - **Windows 어두운 모드 함정:** OS가 어두운 모드면 PySide6가 OS 색을 가져와 "흰 배경에 흰 글자"가 생길 수 있다. ZeroLoss는 **자기 색 팔레트를 강제로 적용**해 OS 테마와 상관없이 같은 색으로 보이게 한다(밝은 테마 하나로 시작, 어두운 테마는 나중에 디자인 값 파일로 추가).
- **글자 크기:**
  - 최소 글자 크기 **9 pt**(100% 배율에서 약 12 px). 그보다 작은 글자는 쓰지 않는다(툴팁·각주 포함).
  - 크기 단계: 본문 10 pt / 제목 12 pt / 핵심 값(Jitter·Loss) 18 pt 이상.
  - **버튼 크기는 글자에 맞춰 자동**(최소 높이 32 px, 좌우 여백 16 px). 글자가 버튼 밖으로 나가거나 잘리면 안 된다. 버튼 글자는 줄이지 말고 버튼을 키운다.
  - 5분 칸 그리드처럼 촘촘한 곳은 칸 안에 글자 대신 **아이콘·색**만, 자세한 값은 마우스를 올리면 툴팁.

**통일성**
- 색·글꼴·간격·아이콘·버튼 모양을 **디자인 값 파일 하나**(`core/ui_schema/design.py`, 색 코드, 크기, 간격)에 정의하고 Controller·Agent Desktop·보고서(HTML)·태블릿 앱이 모두 같은 값을 쓴다. 화면마다 색이 조금씩 다르지 않게.

**검토**
- 화면을 새로 만들거나 바꾸면 **화면 캡처를 남기고** 아래 체크리스트로 검토한다(7장 자동 캡처 활용).
  - [ ] 글자 잘림·겹침·틀 넘침 없음 (1366×768, 1920×1080, 150%, 4K)
  - [ ] 주 버튼 하나, 버튼 위치 규칙 지킴
  - [ ] 간격이 8 px 격자, 정렬선이 맞음
  - [ ] 묶음당 항목 7개 이하, 숨길 것은 숨김
  - [ ] 아이콘 선명, 색 + 아이콘 함께
  - [ ] 모든 글자가 배경과 충분히 대비됨(비활성 글자 포함), 어두운 모드에서도 같음
  - [ ] 9 pt보다 작은 글자 없음, 버튼 밖으로 나간 글자 없음
  - [ ] 처음 보는 사람이 "다음에 뭘 누르지?"를 고민하지 않음

### 1.12 경쟁 상태(race condition) 막기 — 앱 전체 구조 규칙
> 흔한 문제: 두 작업이 동시에 같은 상태·파일을 건드려 순서에 따라 결과가 달라짐. 가끔만 생겨서 재현도 어렵다.
> 이 규칙은 UI뿐 아니라 **Controller·Agent·Deployer·태블릿 앱 전체**에 적용한다.

1. **상태 변경은 한 줄로 세운다:** 공유 상태(상태 저장소, 시험 상태, 장비 상태)는 **하나의 처리 대기열**에서 차례로만 바꾼다. 백그라운드 작업자는 결과를 **메시지로 보내기만** 하고 공유 상태를 직접 고치지 않는다.
2. **모든 비동기 결과에 꼬리표:** `run_id`, `generation`, 요청 ID. 처리 시점에 현재 값과 다르면 **버린다**(늦게 온 옛 응답이 새 상태를 덮어쓰지 못하게).
3. **판단은 처리 시점에:** 버튼을 누른 순간이 아니라 명령을 **실제로 처리할 때의 상태**로 허용 여부를 판단한다(누른 사이 상태가 바뀌었을 수 있음).
4. **같은 작업은 한 번에 하나(single-flight):** 보고서 생성, 설치, 업데이트, 원복, 장비별 프로세스 시작·정지는 진행 중이면 두 번째 요청을 **새로 시작하지 않는다.** 같은 요청(같은 `command_id`, 02 3)이 다시 오면 진행 중·끝난 작업의 답에 **합류**하고, 다른 요청(예: 다른 패키지 설치)이면 **거부**한다(INS-027, 2026-09-25).
5. **외부 프로세스는 장비별로 순서대로:** 시작 → 확인 → 정지 → **종료 확인** → 다시 시작. 이전 프로세스가 끝나기 전에 새로 띄우지 않는다.
6. **타이머는 상태에 묶는다:** 상태가 바뀌면 그 상태의 타이머를 모두 취소. 타이머가 울릴 때 generation을 다시 확인(정지 후에 울린 타이머가 동작하지 않게).
7. **파일은 쓰는 쪽 하나:** 파일마다 쓰는 주체는 하나. 다른 쪽은 **닫힌 파일만** 읽거나 추가 기록 형식(JSONL)을 끝까지 읽는다. 저장은 임시 파일 → 바꿔치기.
8. **자원 잠금은 정해진 순서로만:** 여러 잠금을 잡아야 하면 항상 같은 순서(교착 방지). 잠금을 잡은 채 네트워크·파일 대기 금지.
9. **Android:** 화면(Activity)과 계측·재생(포그라운드 서비스)을 분리. 화면 회전·재생성과 서비스 연결 순서가 엇갈려도 상태가 서비스에 있으므로 영향 없음.

### 1.13 무한 반복 갱신 막기
| 흔한 원인 | 규칙 |
|-----------|------|
| 화면 값을 설정 → "값 바뀜" 신호 → 저장소 갱신 → 다시 화면 설정 → … (신호 되먹임) | 화면을 그릴 때는 **값이 다를 때만** 설정하고, 그리는 동안은 변경 신호를 막는다. 저장소는 **값이 실제로 바뀔 때만** 알린다 |
| 보고서 파일이 바뀌면 다시 생성 → 생성하면 파일이 바뀜 → … | 자기가 만든 파일을 감시해서 다시 동작하지 않는다. 보고서 생성은 **명시적 요청 1회 = 생성 1회** |
| 결과 웹 페이지가 계속 새로고침 | 진행 중인 시험만 **5초마다 필요한 부분만** 가져오고, 시험이 끝나면 멈춘다. 페이지 전체 새로고침 금지 |
| 앱·프로세스가 죽고 → 자동 재시작 → 또 죽고 … | 재시작 횟수 제한(시간당 3회). 넘으면 멈추고 Problems에 표시 |
| 업데이트 → 상대가 다시 업데이트 → … (Agent ↔ Deployer) | **더 새 버전일 때만** 업데이트. 같은 버전 재설치는 사용자가 [Repair]를 눌렀을 때만 |
| 재시도 무한 반복 | 09-exceptions 0.3(최대 3회) |
- 감시: 같은 화면 요소가 1초에 10번 넘게 다시 그려지거나, 같은 작업이 1분에 5번 넘게 반복되면 개발 로그에 경고. 시험에서 0건.

### 1.14 눌러도 반응이 없거나 실행이 안 되는 것 막기
**누르면 항상 반응한다**
- 모든 클릭은 **0.1초 안에 눈에 보이는 반응**(눌림 표시, 진행 표시, 상태 문구). 오래 걸리는 작업은 진행률과 [Cancel].
- 결과가 준비 안 됐으면 아무 일도 안 일어나는 대신 **이유를 보여준다**. 예: [Show report] → "Generating report… 45%", 끝나면 자동으로 열림.
- 동작이 실패하면 반드시 오류 표시(What/Why/Fix). 브라우저로 보고서를 못 열면 폴더 열기로 대체(RPT-007).

**프로그램이 실행되지 않는 경우 (시작 실패)**
| 원인 | 대책 |
|------|------|
| 이전 실행이 비정상 종료되며 남긴 "실행 중" 잠금 | 잠금 파일에 프로세스 번호 기록 → 그 프로세스가 없으면 **오래된 잠금으로 보고 지운다** |
| 설정 파일 손상 | 백업에서 복원, 없으면 기본값으로 시작하고 알림 |
| 실행에 필요한 부품 누락(Qt 플러그인, Visual C++ 런타임 등, PyInstaller에서 흔함) | 설치 파일에 포함. **깨끗한 Windows에서 설치·실행 시험**을 배포 조건으로 |
| 한글 등이 들어간 경로·사용자 이름 | 모든 경로 유니코드 처리(RPT-002), 이런 사용자 이름으로 시험 |
| 백신 차단 | INS-004 |
| 포트 사용 중 | 해당 기능만 끄고 나머지는 실행(CTL-006) |
- 시작할 때 **시작 단계 표시**(Loading settings… / Connecting…)와 단계별 실패 이유 표시. 창이 뜨기 전에 실패하면 **오류 파일을 남기고 간단한 메시지 창**으로 위치를 알려준다.
- **안전 모드 시작:** 시작에 두 번 연속 실패하면 다음 실행은 기본 설정으로 시작할지 묻는다.

### 1.15 보기 상태(구간·필터·선택) 규칙 — 보고서·실시간 구간 보기
> 시안 검토에서 발견: 버튼을 여러 개 섞어 누르면 값이 보였다 안 보였다 함. 원인은 버튼마다 서로 다른 것을 몰래 초기화했기 때문.

- 보기 상태는 **세 가지로 분리**하고, 버튼은 **자기 것만** 바꾼다.
  | 상태 | 바꾸는 것 | 숫자(요약)에 영향 |
  |------|-----------|-------------------|
  | **구간** (From/To, All·First 1h·Last 1h·Around first red, 끌어서 선택) | 어느 시간대를 볼지 | **있음** — 요약은 항상 이 구간 기준 |
  | **강조 필터** (Highlight red only) | 칸을 흐리게/선명하게 | **없음** — 보기만 바뀜 |
  | **장비 선택** (장비 체크박스) | 어느 장비를 셀지 | 있음 — 숨긴 장비는 요약에서 빠짐 |
- **선택한 칸의 1초 그래프는 계속 열려 있다.** 닫히는 경우는 그 칸이 구간 밖으로 나가거나 그 장비를 숨겼을 때뿐이고, 그때는 **왜 닫혔는지 한 줄 알림**을 띄운다.
- 구간 밖의 칸을 클릭하면 구간을 전체로 넓히고 알린다(조용히 무시하지 않음).
- 현재 보기 상태는 항상 요약 줄에 글로 보인다: "Showing 08h 10m – 09h 25m · Devices: … · red boxes highlighted · Overall result: FAIL (unchanged)".
- **FAIL·INCOMPLETE 보고서는 맨 위 결과 문장 옆에 [Show where it failed] 버튼**을 둔다: 첫 빨강 구간을 선택하고 그 칸의 1초 그래프를 연 상태로 이동.
- 자동 시험: 버튼·체크박스·끌기·클릭을 무작위 순서로 수백 번 섞어 누르고, 매번 "요약 숫자 = 현재 구간·장비로 다시 계산한 값", "그래프가 닫혔으면 알림이 있었음"을 확인한다.

### 2-1. 백그라운드로 도는 시험을 사용자가 아는 방법 (S13)
- **트레이 아이콘은 로그인하면 항상 떠 있다**(Controller Desktop의 작은 부분, 로그인 때 자동 시작). 창을 닫으면 앱이 끝나지 않고 트레이로 들어간다.
- 아이콘 색·모양 = 서비스 상태: 회색(대기), 초록 점(시험 중, 정상), 노랑(주의), 빨강(문제·FAIL), 파랑 원(Stop·정리 중). 색만으로 구분하지 않게 모양도 다르다(11-ui 1.x 대비 규칙).
- 마우스를 올리면: `ZeroLoss — Running 12h 34m / 100h · 3 devices OK · Next result 2:13`.
- 클릭하면 메인 창이 열린다. 오른쪽 클릭 메뉴: Open, Last report, Stop test(확인 창), Quit display only.
- **Windows 알림(토스트):** 시험 시작, 끝(판정), Problems 새 항목(오류 이상), Action Required. 시험 중 창을 처음 닫을 때 "The test keeps running in the background" 한 번.
- 로그인하지 않은 상태·다른 PC에서는: 결과 조회 웹(10993) 첫 화면이 현재 시험 상태를 보여 주고, 송신·수신 PC 상태 창(S11)에도 "Test running — controlled by <Controller 이름>"이 보인다. CLI `zeroloss status`도 같다.
- "Quit display only"는 화면·트레이만 끈다. 서비스와 시험은 계속되며, 다음 로그인 때 트레이가 다시 뜬다.

  - 송신 장비: `Sending 3 ch · 105 Mbps`(송출 중인 채널 수 · 합계 송출 비트레이트).
  - 수신 장비: `CH2  Jitter 2.1 ms  Loss 0  ▶ Playing`. Jitter = 직전 1초 값, **Loss = 측정 시작부터 누적 손실 수**(수신기가 센 `lost_total`, 02 5). 재생 켬이면 직전 1초 `pb`(iptv 3.1)가 `ok`·`drop`·`audio_gap`일 때만 `▶ Playing`, `freeze`·`restart`·`none`이면 `■ Not playing`(2026-09-25). 재생 끔이면 표시 없음. 안정화 중이면 `CH2  Warming up`.
  - 한 PC가 송신·수신을 같이 하면(루프백) 한 줄에 송신 → 수신 순서로 둘 다.
  - **아이콘·색 = 직전 1초 값 즉시 + 이번 5분 칸의 나쁜 색 유지:** 직전 1초에 손실 → ✖ 빨강(손실이 모두 수신 장비 자체 드롭으로 설명되면 ◆ 보라, 05 5.3), Jitter ≥ S-23(주의 기준) → ⚠ 노랑, 아니면 ✔. 아직 닫히지 않은 이번 5분 칸 안에서 나온 가장 나쁜 색을 그 칸이 끝날 때까지 유지한다(순간 문제가 1초 뒤 사라지지 않게). 칸이 닫히면 확정 색은 5분 칸 줄에 남는다. 이유는 아이콘 툴팁(`why`).
  - Controller가 덮어쓰는 것(모든 모듈 공통): 마지막 heartbeat 뒤 3 s 이상(`age_s`) → ○ 회색 + `Last update 12 s ago`(1.5, Stale), 시험 밖(IDLE) → ○ + 주소 + `Idle`.
  - 구현: `controller/ui/main_window.py`(창), `view.py`(표시 값, Qt 없음), `texts.py`(문구 파일 1.7), 모듈 `live_row()`. 시험: `tests/controller_ui/test_view.py`·`test_main_window.py`(offscreen, 몽키 포함), `tests/iptv/test_live_row.py`.
  - 상태 줄(시험 중 한 줄): `✔ Running normally. Next 5-min result in 2:13.`(`cell_s` 기준), 노랑·빨강 줄이 있으면 그 장비 이름과 이유. 진행: `12h 34m / 100h (12%)`(Start/Stop 아래).
  - **시험이 끝나면 상태 줄 = 판정 한 줄(2026-10-03 사용자 "뭘 보라는 건지", GAP-106):** 크고 굵게, 판정이 맨 앞 — `PASS — no packet lost, max jitter 2.9 ms. 1 note, the verdict stands: delay variation 84.1 ms > 40 ms (DVB).` / `FAIL — 2 packets lost: network loss 2; TR 101 290 P1 errors 1.` / `INCOMPLETE — <끝난 이유>.` 참고(노랑)는 "the verdict stands"를 함께 써서 실패로 읽히지 않게, 빨강 이유는 FAIL 뒤에. 값은 끝난 회차 `result`(02 10)에서만. 넘치면 말줄임 + 툴팁(1.11).
- 상태창(아래)은 Start 중에는 단계 체크리스트(F17), 시험 중에는 한 줄 상태.
  - 구현(2026-09-25, 03 F17 구현 규칙): 대기 중에는 화면이 30초마다·계획이나 장비 목록이 바뀔 때 가벼운 점검(1~4)을 부르고(`controller/ui/store.py` `IdleCheck`, 화면 스레드 밖), 실패하면 Start 회색 + 이유 `Tools ready: tsp is not installed on rx`, 상태 줄 `Not ready — …`(빨강). **Start 점검이 어느 단계에서 멈췄으면 상태 줄은 `Did not start — <단계>: <What>. Fix it, then press Start again.`(빨강)** — 아래 체크리스트에 ✖가 있는데 위 줄이 초록 `Ready. Press Start.`이던 것을 실제 창에서 발견(2026-10-04 GAP-115). 기준선(S-54)이면 대기 중 장비 줄의 쪽 표시는 `router WAN/LAN side` 대신 `cable to the other PC, no router`. 옛 계획·장비 목록의 결과는 버린다(`check_key`). 상태창 한 줄 아래 체크리스트: Start 중에는 Start 체크리스트, 대기 중에는 가장 최근의 **실패한** 점검(Start·가벼운 점검 중 새것)만 — `✔ ⚠ ✖ ⏳ ⏸` + 단계 이름 + 한 줄(장비: What), 실패·경고 단계 아래 `Why:`·`Fix:`. 가벼운 점검은 5~7단계를 줄에 넣지 않는다. 표시 값 `view.py` `checklist_lines`.
- **Wi-Fi 채널·대역폭 표시 (NET-016/017, 2026-09-24 사용자 요구):** 무선 수신기만(유선은 표시 없음). 공유기가 스캔 후 채널을 자주 옮기므로 무선 결과는 이것부터 본다.
  - 장비 줄: `RSSI −58 dBm · Wi-Fi 36 · 80 MHz` (보조 값, 가늘게). 바뀌면 `⚠ Wi-Fi 36→149 · 80→40 MHz (12:34)`를 그 시험 끝까지 줄에 남기고 툴팁에 전체 이력.
  - Problems ⚠: What `Tablet-2 Wi-Fi changed: channel 36 → 149, 80 → 40 MHz (12:34:56)` / Why `The router moved its Wi-Fi channel (auto channel, radar/DFS or band steering). Packets can be lost while it moves and less can be sent on a narrower channel.` / Fix `To compare, fix the router's Wi-Fi channel and width, then test again.`
  - 상태 줄·S3 그래프·5분 칸 줄에 세로 표식 `Wi-Fi 149/40`. 그 뒤 칸 설명 맨 앞에 Wi-Fi 채널·대역폭.
  - 보고서: 무선 수신기 요약 맨 앞에 RSSI·연결 속도와 함께 **Wi-Fi 이력 표**(시각, BSSID, 대역, 채널, 대역폭, RSSI).
  - **용어:** 무선 채널은 항상 `Wi-Fi channel`/`Wi-Fi 36`, IPTV 채널은 `CH1`/`TV channel`. `Channel` 단독 금지(1.7-1).
- **보고서 맨 위 순서:** ① 측정 신뢰도(F25) ② 판정 ③ 지난 시험 대비 바뀐 것(F24) ④ 무선 수신기는 RSSI·Wi-Fi 이력 ⑤ 5분 결과. 내용 정의는 각 절에만 둔다.
- **링크 속도 알림 (NET-013/014/015, 2026-09-24 사용자 요구):** 모르고 다른 곳에서 원인을 찾는 일이 없게 **변한 순간 여러 곳에 동시에** 알린다.
  - 평소: 장비 줄에는 링크를 보이지 않고 툴팁에만 `WAN link 2.5 Gbps full`(화면을 깨끗하게).
  - 바뀌면 장비 줄에 바로 표시: `✔ Sender 10.0.0.2 Sending 3 ch 105 Mbps  ✖ WAN link 100 Mbps` (필요 대역 미만 ✖ 빨강, 충분하지만 낮음 ⚠ 주황). 유선 수신 PC 줄도 같음(`LAN link`).
  - Problems 창(What/Why/Fix): What `Sender PC ↔ router WAN link changed: 2.5 Gbps → 100 Mbps (12:34:56)` / Why `The link renegotiated. This test needs about 132 Mbps, so packets will be lost.`(충분하면 `Still enough for this test, but slower than usual — often a cable or port problem.`) / Fix `Check or replace the cable and port.`
  - 상태 줄: `⚠ WAN link dropped to 100 Mbps at 12:34:56 — losses after this point are likely from the link.`
  - 필요 대역 미만·끊김은 **Action Required 창**(F22)에도(사람이 케이블을 봐야 하므로). 알림 모듈(메신저·이메일, 14장)도 같은 글.
  - S3 그래프와 5분 칸 줄에 변화 시각 세로 표식 `Link 100M`. 그 뒤 빨강 칸의 설명 맨 앞에 `WAN link at 100 Mbps since 12:34`.
  - 사전 점검(F17 3단계): `Sender WAN link 1 Gbps (usually 2.5 Gbps) ⚠` — 충분하면 시작은 허용, 미만이면 차단(NET-012).
  - 보고서 "시험 환경": NIC별 링크 이력 표(시각, 속도, 이중 방식, 끊김).
  - 구현(2026-09-24): 판단 `controller/links.py`(02 2-1 `link_checks`), 장비 줄·툴팁·상태 줄 `controller/ui/view.py`, Problems·Action Required 창(F21·F22, 2026-09-25). 아직: S3 그래프·5분 칸 세로 표식, 보고서 링크 이력.
- **재생 상태(▶ Playing)는 재생기 자체 보고로만 정한다**(표시 프레임 수가 늘고 있을 때만). 프로세스가 있거나 분석기 값이 올라온다고 Playing으로 보이지 않는다. 늘지 않으면 "■ Not playing" + Problems(RCV-019/020, TAB-015/016). 이전 버전에서 재생기가 안 켜졌는데 분석 값만 올라와 정상처럼 보인 사례(PC·태블릿 모두) 때문(20장 GAP-20).
- **RSSI(무선 신호 세기) 표시 (2026-09-24 사용자 요구, 20장 GAP-09):** 무선으로 받는 수신기만 보인다 — 태블릿, 그리고 **무선 NIC로 받는 PC 수신기**. **유선 수신 PC에는 보이지 않는다**(칸 자체를 숨김, "—"로 채우지 않음).
  - 장비 줄: `Jitter 2.1 ms  Loss 0  RSSI −58 dBm` — Jitter·Loss보다 가늘게(보조 값). 예: `✔ Tablet-1 CH1  Jitter 2.1 ms  Loss 0  RSSI −58 dBm ▸`
  - 신호가 약하면 값 옆에 ⚠와 툴팁 "Weak Wi-Fi signal (below −70 dBm)". 기준은 원인 분석 규칙 R-04(iptv 2장)의 −70 dBm을 그대로 쓴다(새 기준을 만들지 않음). **판정·칸 색에는 영향 없음**(원인 분석 후보에만 쓰임).
  - S3(장비 상세): 1초 목록에 RSSI 열, 그래프에 RSSI 선(따로 축). 5분 칸 툴팁에 그 5분의 최소 RSSI.
  - **왜 먼저 보는가(사용자 설명):** 거리가 멀어 약전계면 재전송이 많아지거나 전송 속도(link rate)가 떨어져, 실제 재생에 필요한 양만큼 패킷이 가지 못한다. 그래서 무선 결과는 **RSSI를 먼저 보고** 상황을 판단한다.
  - 보고서: 무선 수신기는 장비 요약과 문제 칸 설명의 **맨 앞에 RSSI·연결 속도**(5분별 최소 RSSI, 최소 연결 속도 = 02 6장 `wifi.rssi_dbm_min`·`link_mbps_min`)를 두고, 그다음 Loss·Jitter. 빨강·노랑 칸의 설명에는 그 칸의 최소 RSSI를 함께 적는다. 유선 수신기는 이 열 없음.
  - 값이 없으면(읽기 실패) "RSSI —" + 툴팁 "Wi-Fi signal not available"(Unavailable 상태, 4장).

## 4. 화면 요소별 상태 (모든 요소가 모든 상태를 가져야 한다)
| 상태 | 뜻 | 표시 |
|------|----|------|
| Loading | 값을 가져오는 중 | 스피너 + "Loading…" (빈 칸이나 0으로 보이지 않게) |
| Empty | 자료 없음(정상) | 안내 문구 (예: "No report yet. Run a test first.") |
| Normal | 정상 값 | 값 + 색 아이콘 |
| Stale | 값이 오래됨 | 회색 + "Last update Ns ago" |
| Disconnected | 장비 연결 끊김 | ○ 회색 + "Disconnected" + [Retry] |
| Error | 오류 | ✖ + What/Why/Fix 공통 부품 |
| Locked | 시험 중 변경 불가 | 회색 + 툴팁 |
- 화면 부품을 만들 때 **이 7가지 상태를 모두** 만들었는지 확인한다(빠지면 완료 아님).

## 6. Agent Desktop·태블릿 앱 UI
- 같은 원칙을 따른다: 상태는 Agent Service(태블릿은 앱 서비스)가 가진 값만 보여주고, 화면은 보기 전용.
- 재생 화면과 상태 표시는 **서로 다른 부품**. 상태 표시를 갱신해도 재생에 영향이 없게(05-standards 4.2).
- 태블릿: 가로·세로·창 크기 변화 대응(D44), 재생기는 화면 회전 시 다시 만들지 않는다.
