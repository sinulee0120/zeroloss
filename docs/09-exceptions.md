# 09. 예외 상황 목록 (Exception Catalog)

> 목적: 코딩 중에 예외를 발견하고 덧대는 일을 없앤다. **여기 있는 모든 상황은 처음 구현할 때 함께 처리한다.**
> 새 예외를 발견하면 코드보다 **이 문서에 먼저 추가**하고 구현한다.

## 0. 공통 규칙 (모든 예외에 적용)

### 0.1 예외마다 정해야 하는 5가지
| 항목 | 내용 |
|------|------|
| **감지** | 무엇으로 알아채는가 (타임아웃, 카운터, 이벤트, 점검) |
| **처리** | 자동으로 무엇을 하는가 (재시도, 재시작, 정지, 원복) |
| **안내** | 화면에 무엇을 보여주는가 (What / Why / Fix 한 줄씩 + 해결 버튼) |
| **기록** | `events.log`에 오류 코드와 함께 남긴다 |
| **판정 영향** | 5분 칸 색·최종 판정에 어떻게 반영되는가 (`05-standards.md` 5.3~5.4) |

### 0.2 오류 코드
- 형식: `ZL-<영역>-<번호>` (예: `ZL-SND-004`). 영역: `INS`(설치), `DSC`(발견·연결), `SND`(송신), `NET`(네트워크·DUT), `RCV`(수신 PC), `TAB`(태블릿), `CTL`(Controller), `RUN`(시험 진행), `RPT`(보고서), `USR`(사용자 조작), `TIM`(시간), `SYS`(PC·태블릿 공통 자원·내부 결함, 7-1절)
- 화면 안내, 로그, 보고서, 설명서 문제 해결 장에서 **같은 코드**를 쓴다.

### 0.3 공통 처리 원칙
1. **조용히 넘어가지 않는다.** 모든 예외는 기록하고, 사용자에게 영향이 있으면 표시한다.
2. **재시도는 횟수와 간격을 정해서:** 기본 3회, 1초 → 2초 → 4초. 무한 재시도 금지. 재시도 중에도 상태창에 표시.
3. **모든 대기에는 타임아웃:** 기본값은 0.4 표. 타임아웃 없는 대기 금지.
4. **명령은 중복 실행돼도 안전하게:** 모든 명령에 시험 ID + 명령 ID. 같은 명령이 두 번 와도 한 번만 실행.
5. **시스템을 바꾼 상태로 방치 금지:** 예외로 멈출 때도 원복 절차(F13)를 밟고, 원복 실패는 따로 알린다.
6. **측정 자료는 예외보다 우선 보존:** 어떤 예외에서도 이미 받은 자료는 먼저 저장하고 처리한다.
7. **화면(UI)이 멈추면 안 된다:** 네트워크·파일·외부 프로그램 작업은 모두 UI 스레드 밖에서.
8. **숫자는 넘치지 않게:** 패킷 수 등 누적 카운터는 **64비트**. (100시간 × 3채널 × 초당 약 3,300패킷 ≈ 36억 → 32비트 한계 43억에 근접)
9. **시간은 두 가지로:** 간격 계산은 **단조 시계**(시계 변경에 영향 없음), 기록·표시는 **UTC 저장 + 현지 시각 표시**.

### 0.4 기본 타임아웃
| 대상 | 기본값 |
|------|--------|
| heartbeat 응답 | 1초 (3회 연속 실패 = 의심, 10회 = 사망) |
| 일반 제어 명령 응답 | 5초 |
| 송출 시작 → 송출 확인 | 10초 |
| 채널 가입 → 첫 패킷 | 5초 |
| 첫 패킷 → 첫 PAT | 2초 |
| 재생기 시작 → 첫 화면 | 10초 |
| 원복 한 단계 | 15초 |
| SSH 접속 | 15초 |
| 패키지 전달(10991) | 파일 크기 ÷ 1 MB/s + 30초 |
| adb 명령 | 10초 (설치는 120초) |
